# Runforge — страница Runs

Тестовое задание Junior Frontend: дашборд запусков AI-агентов. Здесь есть список запусков, поиск, фильтр по статусу, сортировка и подробности запуска в выезжающей панели (drawer). Данные отдаёт локальный mock-сервис с задержкой.

**Стек:** React 19, TypeScript, Vite, CSS Modules, Vitest и React Testing Library.

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev        # http://localhost:5173
```

| Команда             | Что делает                                       |
| ------------------- | ------------------------------------------------ |
| `npm run dev`       | dev-сервер Vite                                  |
| `npm test`          | все тесты один раз (Vitest + RTL)                |
| `npm run test:watch`| тесты в watch-режиме                             |
| `npm run typecheck` | проверка типов TypeScript                        |
| `npm run build`     | проверка типов и production-сборка в `dist/`     |
| `npm run preview`   | локальный просмотр production-сборки             |

### Как увидеть состояния

- **Загрузка.** Mock-запрос длится около 0,9 с, и в это время показывается skeleton. Кнопка **Refresh** запускает загрузку заново.
- **Ошибка.** Откройте `http://localhost:5173/?mock=error`. Первый запрос завершится ошибкой 503, а кнопка **Retry** загрузит данные.
- **Пустой результат.** Введите в поиск строку, которой нет в данных (например, `zzz`). Появится сообщение и кнопка сброса поиска и фильтров.
- **Детали.** Нажмите на любую строку. Закрыть панель можно кнопкой «Back to runs», клавишей `Esc`, кликом по затемнённому фону или кнопкой «Назад» в браузере.

## Что реализовано

**Обязательное**
- Список запусков: название, репозиторий и ветка, статус, дата создания, длительность. Если длительности нет, выводится «—», а для running выводится «In progress».
- Фильтр All / Queued / Running / Succeeded / Failed. У активного фильтра тёмная заливка и `aria-pressed`. На каждой кнопке есть счётчик, и он учитывает текущий поиск.
- Поиск по названию и репозиторию без учёта регистра. Поиск работает вместе с фильтром.
- Детали запуска: метаданные, результат (или пояснение, почему его нет) и логи с номерами строк. Строки с `ERROR` подсвечены.
- У каждого статуса свой цвет, своя иконка и текстовая подпись, поэтому статусы различаются и без цвета.
- Состояния загрузки (skeleton), ошибки (Retry) и пустого результата (сброс фильтров).
- Адаптивная вёрстка начиная с 360 px. До 760 px таблица превращается в карточки с подписями полей (Repository, Created, Duration). До 900 px сайдбар прячется и выезжает слева по кнопке меню.

**Бонусы**
- Сортировка: сначала новые или старые, по длительности в обе стороны. Запуски без длительности всегда стоят в конце.
- URL-фильтры: поиск, статус, сортировка и открытый запуск хранятся в адресе (`/?status=failed&q=payments&run=run_1f4e07`). Ссылкой можно поделиться, и состояние переживает перезагрузку.
- Клавиатура: `/` переводит фокус в поиск, `Esc` очищает поиск, закрывает панель деталей и мобильное меню. Строки списка сделаны кнопками, поэтому работают Tab и Enter. В панели и в меню фокус не выходит за их пределы, а после закрытия возвращается туда, откуда их открыли. У всех элементов одинаковое кольцо фокуса.
- Дополнительные тесты: пустое состояние, ошибка и Retry, восстановление из URL, утилиты форматирования и сортировки.

## Тесты

`npm test` запускает 23 теста в четырёх файлах:

- `src/pages/RunsPage/RunsPage.test.tsx` — интеграционные тесты страницы: загрузка, **фильтрация по статусу**, **поиск** (в том числе вместе с фильтром), **открытие деталей** и возврат к списку, закрытие по Esc при отсутствующих длительности и результате, Esc после клика по тексту в панели, пустое состояние и сброс, ошибка и Retry, восстановление состояния из URL.
- `src/components/AppLayout/AppLayout.test.tsx` — мобильное меню: открытие кнопкой, закрытие по Esc и крестиком, удержание фокуса по Tab, возврат фокуса на кнопку.
- `src/utils/runQuery.test.ts` — фильтрация, поиск и сортировка, подсчёт по статусам.
- `src/utils/format.test.ts` — форматирование дат и длительности, в том числе некорректные значения.

Вручную проверено в браузере на ширине 360, 375, 760/761, 900/901 px и на десктопе. Ошибок в консоли нет.

## Структура проекта

```
src/
├── api/
│   ├── mockRuns.ts            # 8 тестовых запусков, есть все 4 статуса
│   └── runsService.ts         # mock «GET /api/runs»: Promise, задержка, AbortSignal, режим ошибки
├── types/run.ts               # Run, RunStatus, StatusFilter, SortOrder
├── hooks/
│   ├── useRuns.ts             # загрузка: loading / error / success, reload, отмена запроса
│   ├── useRunsUrlState.ts     # поиск, фильтр, сортировка и открытый запуск, синхронизированные с URL
│   └── useModalBehavior.ts    # общее поведение модальных окон: фокус, Tab, Esc, блокировка прокрутки
├── utils/
│   ├── runQuery.ts            # чистые функции: поиск, фильтр, сортировка, подсчёт
│   └── format.ts              # даты и длительность
├── components/
│   ├── AppLayout/             # сайдбар (на узких экранах выезжающее меню) и основная область
│   ├── RunsToolbar/           # SearchInput, StatusFilter, SortSelect
│   ├── RunList/               # RunList, RunListItem, RunListSkeleton
│   ├── RunDetails/            # RunDetailsDrawer, RunDetailsContent, RunResult, LogViewer
│   ├── StateMessage/          # общий блок состояния: EmptyRunsState и RunsErrorState
│   ├── StatusBadge/
│   └── Button/
├── pages/RunsPage/            # собирает страницу из хука данных, URL-состояния и компонентов
├── styles/global.css          # дизайн-токены: цвета, отступы (шаг 4 px), шрифты
└── test/setup.ts
```

**Несколько решений:**
- Сервис данных передаётся в `RunsPage` через проп `loadRuns`. Поэтому в тестах можно передать сервис без задержки или с ошибкой, и ничего не приходится мокать.
- Фильтрация и сортировка вынесены в чистые функции (`utils/runQuery.ts`), а компоненты только отображают результат.
- Режим ошибки в mock-сервисе срабатывает в момент завершения запроса, а не при его старте. В StrictMode React запускает эффект дважды, и первый запрос отменяется. Если бы ошибка решалась при старте, отменённый запрос «съедал» бы её, и состояние ошибки никогда бы не появилось.
- Панель деталей и мобильное меню используют общий хук `useModalBehavior`. Esc он слушает на всём документе, поэтому Esc срабатывает, даже если после клика по тексту фокус ушёл с кнопок.
- Когда панель деталей открывается, в историю добавляется запись (`pushState`). При закрытии выполняется `history.back()`, поэтому кнопка «Назад» в браузере тоже закрывает панель и записи в истории не копятся.

Интерфейс на английском, как в макете и в названиях фильтров из задания.
